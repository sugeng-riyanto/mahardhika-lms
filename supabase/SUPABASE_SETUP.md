## 1. Database Migrations (SQL Editor)

Open **Supabase Dashboard → SQL Editor → New query**, paste the full content of
each file below **in order**, and click **Run**:

| # | File | Status | Purpose |
|---|------|--------|---------|
| 1 | `supabase/migrations/001_initial_schema.sql` | ✅ Already applied by you (identity, orgs, courses) | Core schema |
| 2 | `supabase/migrations/002_rls_policies.sql` | ✅ Applied — user-level policies version | RLS helpers + core table policies |
| 3 | `supabase/migrations/003_domain_rls_policies.sql` | ⬜ **Run this now** | RBAC policies on 30+ domain tables |
| 4 | `supabase/migrations/004_storage_buckets.sql` | ⬜ **Run this now** | Private buckets + storage policies |

> **IMPORTANT — order of operations:** the domain tables (grades, essays,
> invoices, …) do NOT exist until Django migrations run against Supabase.
> Migration 003 will fail with `relation "public.grades" does not exist` if you
> paste it first. Correct order:
>
> 1. Put your real connection string in `backend/.env`:
>    ```
>    SUPABASE_DATABASE_URL=postgresql://postgres:REAL_PASSWORD@db.stfrztjpunetsekovlsk.supabase.co:5432/postgres
>    ```
> 2. Push all Django tables to Supabase:
>    ```bash
>    cd backend
>    python manage.py migrate --settings=config.settings_supabase
>    python manage.py seed_data --settings=config.settings_supabase
>    ```
> 3. THEN paste 003 and 004 into the SQL Editor.
>
> Local development stays on SQLite — `config.settings_supabase` only affects
> these explicit commands. Never commit the real password.

### Verify RLS is active

Paste this into the SQL Editor and confirm every row shows `rls_enabled = true`:

```sql
SELECT tablename, rowsecurity AS rls_enabled
FROM pg_tables
WHERE schemaname = 'public'
  AND tablename IN ('grades','invoices','notifications','essay_responses',
                    'safeguarding_reports','canvas_documents','certificates')
ORDER BY tablename;
```

## 2. Authentication Settings

Dashboard → **Authentication → Sign In / Providers**

- [ ] Enable the **Email** provider (password-based).
- [ ] **Disable "Allow new users to sign up"** for production (users are created
      by Admin/Django only). Keep it enabled during development if convenient.
- [ ] Set **Minimum password length** ≥ 10.

Dashboard → **Authentication → URL Configuration**

- [ ] **Site URL**: your production URL (e.g. `https://akademi.example.id`).
      For local dev: `http://localhost:5173`.
- [ ] **Redirect URLs** — add both:
  - `http://localhost:5173/**`
  - `https://<your-production-domain>/**`

Dashboard → **Authentication → Sessions**

- [ ] Access token lifetime: default 3600s is fine.
- [ ] Enable **Refresh token rotation** (recommended).

Dashboard → **Auth → MFA** *(production hardening)*

- [ ] Enable TOTP factor for Owner/Admin/Treasurer accounts.

## 4. Storage

Running `004_storage_buckets.sql` creates 4 **private** buckets:

| Bucket | Contents | Size limit |
|--------|----------|-----------|
| `content-library` | course materials | 50 MB |
| `submissions` | student assignment files | 25 MB |

Verify in Dashboard → **Storage**: all four exist and show 🔒 **Private**
(not public). Access happens exclusively through short-lived signed URLs
generated by Django.

Nothing else to configure here unless you want lifecycle rules.

## 5. API Keys & Secrets

Dashboard → **Project Settings → API**

- [ ] Copy the **Publishable / anon key** → put in `frontend/.env.local`
      as `VITE_SUPABASE_PUBLISHABLE_KEY`. Safe to expose.
- [ ] Copy the **Secret / service_role key** → put ONLY in `backend/.env`
      as `SUPABASE_SECRET_KEY`. **Never** in frontend code or Git.
- [ ] Copy the **JWT Secret** → keep for reference; used by Django JWKS/JWT verification.
- [ ] Confirm no secret key appears anywhere under `frontend/`.

Dashboard → **Project Settings → Database**

- [ ] Copy the connection string into `backend/.env` as `DATABASE_URL`
      (replace `[YOUR-PASSWORD]` with the real DB password).
      Use port **6543** (pooled / transaction mode) for app runtime,
      port **5432** for migrations.
